# ZILAL TRAVEL — первый этап бэкенда

FastAPI + PostgreSQL, миграции Alembic и подключённый Next.js. Реализованы защищённый вход, общий контент, черновики, публикация, история и конфликт версий. Публичные страницы и метаданные читают данные с сервера. Админка использует тот же домен через ограниченные маршруты Next.js, с HttpOnly-сессией и CSRF-защитой.

Этот этап не включает реальные заявки, CRM, загрузку фотографий и оплату. В серверном режиме эти разделы не доступны как рабочие; локальное демо сохраняется отдельно. Публичные цены, программы и отзывы из примеров не становятся подтверждёнными предложениями автоматически.

## Бесплатный запуск на Windows (PowerShell)

Потребуются Node.js 24, Python 3.12 или новее и Docker Desktop. Docker нужен только для локального PostgreSQL. Для корпоративного использования Docker Desktop действуют собственные лицензионные условия; проверьте, применим ли бесплатный вариант к вашей организации. Облачный запуск с Neon не требует Docker Desktop.

Из корня проекта:

```powershell
py -m pip install uv
py backend/tools/setup_local.py
docker compose up -d --wait
cd backend
py -m uv sync --frozen
py -m uv run --frozen alembic upgrade head
py -m uv run --frozen python -m app.cli import-content initial-content.json
py -m uv run --frozen python -m app.cli import-content initial-content.json --apply
py -m uv run --frozen python -m app.cli create-user --email you@example.com --name "Владелец"
py -m uv run --frozen uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Замените `you@example.com` своим email. Команда попросит пароль дважды: минимум 12 символов, ввод не отображается. Пароля по умолчанию нет. Пользователи не создаются через публичную регистрацию.

Оставьте это окно открытым. Во втором окне PowerShell из корня проекта:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:3000` и `http://localhost:3000/login`; после входа — `/admin`. Если PowerShell блокирует npm.ps1, используйте `npm.cmd` вместо `npm`.

Скрипт `setup_local.py` создаёт `.env`, `backend/.env` и `frontend/.env.local` со случайным паролем локальной базы и серверным режимом. Эти файлы не коммитятся. Если какой-либо файл уже существует, скрипт ничего не заменяет. При существующей конфигурации сверяйте примеры `.env.example`: пароль в корневом `.env` должен совпадать с паролем в `DATABASE_URL`; `SITE_ORIGIN` на frontend и backend должен в точности совпадать с адресом браузера (включая порт). В development используются HTTP и локальный адрес; в production обязательны HTTPS, `APP_ENV=production` и Secure-cookie.

Если хотите прежнее локальное демо, задайте в `frontend/.env.local` `PLATFORM_MODE=demo` и перезапустите frontend. Не меняйте рабочее облачное размещение на демо ради обхода ошибки API.

Данные базы сохраняются в Docker volume. `docker compose down` останавливает базу без удаления данных. Не используйте `down -v`: это удалит локальную базу. Остановка каждого сервера — `Ctrl+C`.

## Миграции и импорт

`alembic upgrade head` создаёт/обновляет схему. Импорт без `--apply` проверяет файл и откатывает транзакцию; с флагом применяет изменения. Импорт поддерживает JSON прежнего localStorage и сохраняет публичные slug. ID получают префикс коллекции, чтобы одноимённые тур и направление имели разные серверные ID; ссылки пересчитываются.

Уже существующие ID/slug перечисляются и пропускаются, а не перезаписываются. Повторный импорт не создаёт дубликаты. Совпавшие записи не обновляются массово: редактируйте их через админку. Ошибка в новых данных откатывает всю транзакцию. Из файла берётся только публичный контент и настройки при их отсутствии; фиктивные клиенты, платежи, лиды и сотрудники не импортируются. У существующих настроек приоритет перед импортом.

Начальные данные включены в `initial-content.json`. Это снимок текущих публичных примеров frontend; его обновление не заменяет уже сохранённые серверные данные.

## Проверки

Тесты используют отдельную базу `zilal_test` и очищают только её. Рабочий адрес базы тестам передавать нельзя. Из корня один раз создайте тестовую базу:

```powershell
docker compose exec postgres createdb -U zilal zilal_test
cd backend
py -m uv run --frozen python tools/test.py
py -m uv run --frozen ruff check app tests migrations tools
```

Повторно создавать уже существующую `zilal_test` не нужно. `tools/test.py` рассчитан только на локальную базу и сохраняет код завершения pytest. Для CI задаётся `TEST_DATABASE_URL`, указывающий на отдельную базу с именем `zilal_test`, выполняются её миграции и затем `pytest`.

## Резервная копия

Для бинарного дампа избегайте перенаправления stdout в старых версиях Windows PowerShell. Из корня:

```powershell
docker compose exec postgres pg_dump -U zilal -d zilal -Fc -f /tmp/zilal-backup.dump
docker compose cp postgres:/tmp/zilal-backup.dump ./zilal-backup.dump
```

В дампе могут быть данные сотрудников и хеши паролей. Храните его приватно, не загружайте в GitHub. Резервная копия не считается проверенной, пока не восстановлена в отдельную базу:

```powershell
docker compose exec postgres createdb -U zilal zilal_restore_test
docker compose cp ./zilal-backup.dump postgres:/tmp/zilal-backup.dump
docker compose exec postgres pg_restore -U zilal -d zilal_restore_test --no-owner --no-acl /tmp/zilal-backup.dump
```

Проверяйте данные в `zilal_restore_test`. Не восстанавливайте поверх рабочей базы без отдельного плана переноса.

## Первый бесплатный облачный запуск — отдельно

Рабочее размещение ещё не выполнено, аккаунты и актуальные бесплатные тарифы пока не подтверждены. Предварительный вариант — Netlify Free + Render Free + Neon Free. Нужны только бесплатные аккаунты; при обязательной оплате выбирается другой вариант. Секреты вводятся через настройки платформ, не в чат.

- Backend: корневая папка `backend`; установка `pip install --require-hashes -r requirements.txt`; старт `uvicorn app.main:app --host 0.0.0.0 --port $PORT` (команда Linux на платформе). Задать Python 3.12+, `DATABASE_URL`, `SITE_ORIGIN`, `APP_ENV=production`. Применить миграции и импорт отдельно. Первого владельца создать безопасной командой; временные тестовые аккаунты из облачной среды не переносятся.
- Frontend: корневая папка `frontend`; `npm ci` и `npm run build`, адаптер Next.js платформы. `PLATFORM_MODE=server`, HTTPS `BACKEND_URL` и точный HTTPS `SITE_ORIGIN`. Адрес API и секреты базы не помещаются в `NEXT_PUBLIC_*`.
- Не запускайте миграции или наполнение на каждом HTTP-запросе. Укажите подходящий PostgreSQL URL `postgresql+psycopg://…` с TLS для облачной базы. Проверяйте ограничения бесплатной базы и доступность резервных копий.

Сейчас публичные данные читаются без межзапросного кеша для надёжной видимости публикации. Это подходит малому пилоту; до роста трафика требуется контролируемое кеширование с инвалидированием. Ограничение входа — 10 попыток за 15 минут на IP клиента API; при Next.js-посреднике IP общий, поэтому лимит консервативно общий для сотрудников. Для большой команды потребуется ограничение по пользователю и доверенному прокси.

Переводы подготовлены таблицами с кодом языка, API первого этапа работает с русским контентом. Email-сброс пароля, приглашения, 2FA, управление пользователями из интерфейса и автоматическая очистка старых сессий пока не реализованы. Пользователи создаются CLI. Публичные финансовые операции и сбор клиентских данных не включены.

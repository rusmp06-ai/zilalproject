# Проверка frontend ZILAL TRAVEL

Проверено в текущей облачной среде: Node.js 24, Next.js 16, Chromium. Проверки относятся к локальному frontend с демонстрационными данными, а не к реальному бронированию или опубликованному сайту Vercel.

## Выполненные проверки

- Производственная сборка `npm run build` и строгая проверка TypeScript.
- 30 представительных публичных и административных адресов на ширинах 390, 768 и 1440 px: ответы HTTP 200, отрисовка и отсутствие горизонтального переполнения страницы. Широкие таблицы и воронка прокручиваются внутри своих контейнеров.
- Поиск, фильтр однодневных туров и пустое состояние каталога.
- Создание нового тура, программа из двух дней, открытие по новому slug, изменение названия, появление изменения на сайте и сохранность после перезагрузки.
- Создание и восстановление записей в остальных 11 коллекциях: направления, впечатления, журнал, галерея, отзывы, лиды, клиенты, бронирования, партнёры, платежи и сотрудники.
- Пошаговая заявка на выбранный тур: неопределённые даты, интересы, бюджет и контакты; появление лида в CRM.
- Смена статуса лида в воронке и сохранность статуса после перезагрузки.
- Изменение заголовка главной в настройках и отображение нового текста на сайте.
- Блокировка удаления тура со связями; удаление несвязанного тура и состояние недоступного материала.
- Мобильная навигация публичного сайта и админки.
- Экспорт JSON, возврат к примерам, импорт экспортированного файла и восстановление изменённого контента.
- Отклонение импорта неподходящего JSON без подмены текущих данных.
- Повреждённая локальная копия: сообщение об ошибке, показ исходных примеров и сохранение повреждённого содержимого до явного действия пользователя.
- Основной цикл создания тура, планирования, CRM, настроек и импорта повторно прошёл на производственном сервере `next start`.
- В основных функциональных сценариях не обнаружены ошибки выполнения JavaScript или ошибки консоли браузера.

## Дополнительная проверка после профессионального обзора

- 10 автоматических регрессионных тестов: формат исходных данных, календарные даты, целое число участников, связи, маршруты, дробные денежные суммы, поиск е/ё, повреждённая копия, конфликт версий и отказ записи при переполнении хранилища.
- В Chromium проверены одновременные изменения разных записей в двух вкладках и конфликт при изменении одной записи. Обе независимые правки сохраняются; конфликт не затирает введённый текст.
- Искусственный отказ localStorage не показывает успешное сохранение. Поля остаются заполненными; повторное сохранение после устранения ошибки работает.
- Новые материалы создаются черновиками. Проверены предупреждение при уходе из редактора и независимость новых форм разных разделов.
- Основной цикл каталог → тур → заявка → CRM → настройки → экспорт/импорт повторно пройден после исправлений.
- Автоматический axe-core аудит семи страниц (`/`, `/tours`, `/tours/issyk-kul`, `/plan`, `/admin`, `/admin/bookings/new`, `/admin/settings`) на ширинах 390 и 1440 px: нарушений проверяемых правил WCAG 2 A/AA и 2.1 AA не найдено. Это не заменяет полную ручную проверку доступности.

## Ручная проверка на Windows

```powershell
cd frontend
npm ci
npm run build
npm run typecheck
npm test
npm run dev
```

Откройте `http://localhost:3000/admin/tours`, создайте тур с уникальным slug, заполните обязательные поля и выберите статус «Опубликован». Откройте его через «Посмотреть на сайте», измените название в редакторе и обновите публичную страницу.

Откройте `/plan`, заполните три шага и сохраните пример. В `/admin/leads` найдите его, переключитесь на воронку и смените статус. Обновите страницу и проверьте сохранность.

В `/admin/settings` экспортируйте локальную копию перед сбросом. Верните примеры, импортируйте файл и проверьте, что ваши записи восстановились.

## Границы проверки

Не проверялись и не реализованы: реальные платежи, серверная авторизация, разграничение доступа, внешние уведомления, общая база данных, загрузка фотографий и интеграции. Полный английский перевод новых интерфейсов и контента остаётся отдельным этапом; сейчас тексты вынесены в словари.

Локальные изменения видны только в браузере на текущем адресе сайта. Серверные метаданные берутся из исходных примеров. Неизвестный slug локального материала показывает frontend-состояние недоступности; полноценный HTTP 404 для данных потребует общего серверного источника.

Предупреждение о несохранённых изменениях работает при переходе по ссылке и закрытии/перезагрузке вкладки. Перехват кнопки браузера «Назад» не гарантируется. В браузерах с Web Locks запись между вкладками сериализуется; без этого API применяется проверка текущей копии, но полной гарантии при одновременной записи нет.

## Улучшение выбора маршрута

- В Chromium на 390, 768 и 1440 px проверены фильтр длительности, переход из каталога на Сон-Куль, навигация по разделам, переход в планирование с выбранным маршрутом, пустой результат поиска и сброс фильтров.
- Страница Тянь-Шаня на этих ширинах не имеет горизонтального переполнения; axe-core не обнаружил нарушений проверяемых WCAG 2 A/AA и 2.1 AA правил.
- Новые поля аудитории и условий цены отредактированы в админке; значения появились на публичной странице. Старая копия без новых полей корректно показывает текст об уточнении.
- Пример Ала-Арчи больше не наследует ночёвку, подготовку к многодневному треккингу и включённое проживание. Все описания и цены остаются демонстрационными, требуют редакционного согласования перед реальными продажами.

## Редакционная главная

- Проверены 11 разделов, один H1, основные переходы к каталогу и туру, ссылки внутри страницы, отсутствие горизонтального переполнения на 360, 390, 768 и 1440 px.
- axe-core аудит главной на этих четырёх ширинах: нарушений проверяемых WCAG 2 A/AA и 2.1 AA правил не найдено.
- Изменённый в настройках Hero отобразился на новой главной; удаление демонстрационных коллекций не возвращает скрытые записи.
- Мобильная и настольная композиции просмотрены по снимкам экрана. Фотографии пока заменены SVG и подписанными местами для будущих портретов.

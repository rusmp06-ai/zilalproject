# План подключения бэкенда ZILAL TRAVEL

Статус: техническое предложение; обязательный бюджет первого этапа — 0 USD. Облачные сервисы не созданы, платные тарифы не подключены. Основание: разделы 8–9, 11–20 и 25 архитектуры и текущий Next.js frontend. Этот документ не означает готовность реальных бронирований.

## Первый результат

Владелец входит в защищённую админку, меняет тур, сохраняет черновик и публикует его. Опубликованный контент виден любому посетителю и после смены устройства; черновики доступны только сотрудникам с соответствующими правами. Текущие страницы и редакционный дизайн сохраняются.

Первый этап подключает туры, направления, впечатления, журнал, отзывы и настройки. Галерея пока использует существующие иллюстрации; загрузка фотографий будет отдельным этапом. Примерные отзывы остаются явно отмеченными и не становятся настоящими автоматически.

## Стек и назначение

| Компонент | Решение | Назначение |
|---|---|---|
| Публичный сайт и админка | Существующий Next.js, предварительно Netlify Free | Сохраняем дизайн и маршруты |
| API | Python 3.12+, FastAPI, `/api/v1` | Валидация, публикация, права и бизнес-операции |
| База данных | PostgreSQL | Общие данные, связи и транзакции |
| Модели и миграции | SQLAlchemy 2 + Alembic | Типизированные модели, воспроизводимые изменения схемы |
| Драйвер базы | psycopg 3 | Подключение Python к PostgreSQL |
| Пароли | Argon2id через argon2-cffi | Адаптивное хеширование |
| Тестирование API | pytest + httpx | Проверка доступа, публикации и ошибок |
| Развёртывание API | Предлагается Render Free | Отдельный Python-сервис |
| Управляемая база | Предлагается Neon Free | PostgreSQL отдельно от frontend |
| Будущие фотографии | Бесплатное объектное хранилище, выбор позже | Файлы отдельно от базы; подключение позже |

Платные планы, платный домен и услуги с обязательной оплатой в первый этап не входят. Это предложения по размещению, а не требования архитектуры. Провайдеров можно заменить без смены FastAPI/PostgreSQL. Новые библиотеки интерфейса не нужны. Подготовка репозитория и локального запуска не требует открытия платных аккаунтов.

## Схема запросов и вход

Браузер → Next.js на домене сайта → FastAPI → PostgreSQL.

Next.js предоставляет строго определённые серверные маршруты-посредники для административных операций, а не универсальный прокси. Браузер работает с одним доменом, публичный серверный рендеринг получает опубликованный контент из FastAPI. Это позволяет обновлять и страницу тура, и её SEO-метаданные из одного источника.

Вход по email и паролю для сотрудников, без публичной регистрации. Первого супер-администратора создаёт отдельная команда; пароль не хранится в GitHub и не задаётся стандартным значением. После входа сервер выдаёт случайную непрозрачную сессию: в базе хранится хеш токена, срок жизни, пользователь и возможность отзыва. Cookie — HttpOnly, Secure в production и SameSite=Lax; токены не сохраняются в localStorage. Выход отзывает сессию. Для изменяющих запросов нужны проверка Origin и CSRF-токен. Ограничение попыток входа должно работать на сервере, а не только в браузере; в первом размещении можно хранить состояние в PostgreSQL без отдельного Redis.

Роли соответствуют архитектуре: супер-администратор, администратор, менеджер, контент-менеджер, оператор. На первом этапе рабочие права получают супер-администратор, администратор и контент-менеджер. Менеджер и оператор не получают доступ к редакторам контента; их рабочие модули подключаются на следующих этапах. Проверка прав выполняется FastAPI при каждом действии. Скрытие кнопки в интерфейсе не является защитой.

## Данные

Не переносим универсальный `fields: Record<string, string>` как постоянную модель всех бизнес-данных. В PostgreSQL вводятся отдельные таблицы сущностей, внешние ключи, уникальные slug и типизированные поля. Деньги — точное десятичное значение и код валюты; число дней и участников — целые числа.

Основные таблицы первого этапа: пользователи, роли, сессии, туры, направления, впечатления, статьи, отзывы, настройки, история действий. Для тура — упорядоченные дни программы, включённые/исключённые услуги и FAQ. Тексты хранятся в таблицах переводов с кодом языка: русский обязателен для первой публикации, английский можно добавить позднее. Готовый английский интерфейс не объявляется до фактического перевода.

Поля аудитории, темпа, подготовки, начала маршрута и условий цены сохраняются. У публичных сущностей есть черновик/публикация, время изменения и номер версии. Конкурирующее сохранение старой версии возвращает HTTP 409 с понятным сообщением, а не перезаписывает чужие изменения. Изменение и запись аудита выполняются в одной транзакции.

Опубликованный тур не ссылается на неопубликованное направление. Удаление связанных записей блокируется; архивирование можно добавить по требованиям. Публичный API возвращает только разрешённые поля опубликованных объектов, без сотрудников, сессий, истории и будущих CRM-данных.

## API и подключение frontend

- `POST /api/v1/auth/login`, `POST /auth/logout`, `GET /auth/me`.
- Публичное чтение опубликованного контента: `/api/v1/public/tours`, `/tours/{slug}` и аналогичные маршруты остальных публичных коллекций, плюс разрешённые настройки сайта.
- Защищённые `/api/v1/admin/...`: списки, создание, редактирование с версией, удаление и явная публикация контента; настройки и аудит.
- Реальные неизвестные slug возвращают HTTP 404. Ошибки полей связываются с соответствующими полями формы.
- Слой `frontend/services/` заменяет обращения редакторов к локальному хранилищу. Next.js получает публичные данные на сервере; после изменения контента кеш явно обновляется, с ограниченным сроком жизни как дополнительной страховкой.

Переходный демонстрационный режим задаётся явной конфигурацией. При сбое серверного API сайт не переключается незаметно на localStorage и не показывает ложное успешное сохранение. В серверном режиме неподключённые CRM-разделы не выставляются как рабочие: их демо остаётся доступным только в отдельном демонстрационном запуске. Публичная форма до этапа реальных заявок продолжает явно обозначать свой демонстрационный статус.

## Перенос примеров и локальных правок

1. Экспортировать текущую локальную копию через настройки и сохранить файл отдельно.
2. Создать миграциями пустую базу. Команда начального наполнения добавляет только демонстрационный публичный контент и настройки; не добавляет фиктивные лиды, клиентов, платежи и сотрудников в рабочие данные.
3. Подготовить одноразовый импорт JSON: проверка схемы, связей и типов, отчёт предварительного просмотра и применение в транзакции. Старые ID сопоставляются с серверными; публичные slug сохраняются.
4. Импорт не заменяет базу целиком и не перезаписывает совпавшие записи молча. Конфликты перечисляются в отчёте и разрешаются явно. Повторный запуск не создаёт дубликаты.
5. Сначала выполнить перенос на тестовой базе, проверить страницы и экспорт, затем применить согласованный набор к рабочей базе.

Для первого подключения достаточно исходных файлов `frontend/data/`. Персональные локальные изменения можно перенести после получения экспортированного файла; автоматически прочитать хранилище пользователя из облачной среды невозможно.

## Порядок реализации и проверка

1. Создать `backend/`, зависимости, конфигурацию без секретов, локальный PostgreSQL через Docker Compose, модели и миграции. Добавить инструкции для Windows PowerShell.
2. Реализовать сессии, вход/выход и серверную матрицу прав. Проверить 401 без входа, 403 без права, отзыв и срок жизни сессии, CSRF и ограничение попыток.
3. Реализовать контентное API, публикацию, аудит и конфликт версий. Проверить независимые изменения, запрет публичного чтения черновиков, связи, валидацию и транзакции.
4. Подключить защищённую админку и публичные страницы к API. Проверить публикацию из одного браузера и видимость в другом, сохранность после перезапуска, реальные 404 и новые метаданные.
5. Подготовить тестовое размещение, HTTPS, секреты, резервное копирование и восстановление. Проверить восстановление на отдельной базе, а не только наличие настройки бэкапа.
6. После проверки открыть доступ к первому рабочему этапу. Не удалять локальные экспорты и не включать реальную отправку заявок раньше этапа CRM.

Критерий готовности: редактирование опубликованного тура доступно только разрешённому сотруднику; изменения видны независимому посетителю, сохраняются после рестарта, попадают в аудит, не раскрывают черновики и восстанавливаются из резервной копии.

## Размещение и бюджет: бесплатный старт

Обязательное ограничение владельца: **0 USD в месяц для первого этапа**. Платный тариф, автоматическое повышение тарифа и платные дополнения не подключаются. Не рассчитываем на пробные платные планы с последующей обязательной оплатой. Разработка и тестирование могут выполняться локально бесплатно.

| Ресурс | Предварительный выбор | Что нужно учесть |
|---|---|---|
| Next.js сайт и защищённая админка | Netlify Free | Проверить поддержку используемой версии Next.js, лимиты сборок, серверных запросов и трафика; при исчерпании бесплатного лимита сайт может приостановиться |
| FastAPI | Render Free | Бесплатный сервис может засыпать без запросов; первый запрос после простоя может быть медленным. Постоянные данные не хранятся на его локальном диске |
| PostgreSQL | Neon Free | Ограничены объём и вычислительные ресурсы; возможен холодный старт. Проверить доступные бэкапы и лимиты проектов |
| Адрес сайта | Бесплатный поддомен платформы | Покупка домена не требуется; публичный HTTPS — обязательное условие размещения |
| Репозиторий | Текущий GitHub | Сохраняем код и миграции; не используем репозиторий для клиентских данных и секретов |
| Фото | Пока существующие SVG | Выбор бесплатного медиахранилища и загрузка фотографий — отдельный этап |
| Резервные копии | Ручной экспорт PostgreSQL и проверка восстановления | Не обещаем платный автоматический бэкап или гарантированную доступность; выгрузки хранятся отдельно от GitHub, с ограниченным доступом |

Не используем Vercel Hobby как основу рабочего коммерческого проекта: этот план предназначен для личного некоммерческого использования. Существующий frontend-прототип не удаляем; перенос размещения выполняется после проверки Netlify. Приложение не превращаем в статическую выгрузку: админке и публичным страницам нужны серверные возможности Next.js.

**Статус проверки тарифов:** официальные страницы были запрошены 6 октября 2026 года, но сеть текущей облачной среды вернула 403 на обращение к провайдерам. Поэтому наличие, конкретные квоты, требования карты, условия коммерческого использования и совместимость Next.js этих бесплатных планов пока не подтверждены для текущей даты. Перед регистрацией/размещением проверить официальные условия. Если сервис требует обязательной оплаты, выбрать другой бесплатный вариант или оставить тестовый запуск локальным — бюджет не увеличивать автоматически.

Официальные источники для проверки:

- Netlify: https://www.netlify.com/pricing/ и https://docs.netlify.com/frameworks/next-js/overview/
- Render: https://render.com/docs/free
- Neon: https://neon.com/pricing
- Vercel Hobby: https://vercel.com/docs/plans/hobby

Разработка backend начинается без платных аккаунтов. Публичный тестовый запуск требует бесплатных аккаунтов выбранных платформ; наличие аккаунтов и доступ к ним пока не подтверждены. Секреты добавляются через настройки среды, а не в переписку или исходный код. Регионы размещения согласуются до хранения реальных клиентских данных.

Бесплатное размещение подходит для разработки и небольшого пилота с учётом ограничений. Даже при бюджетном запуске сохраняем защищённый вход, серверные права доступа и валидацию. Ограничиваем лишние запросы, используем кеш публичного контента, показываем понятное состояние ожидания API. Не используем искусственные запросы для обхода засыпания бесплатного сервиса.
